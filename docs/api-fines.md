# Fine & Payment API

The Fine & Payment API allows authorized users to view fines generated by the return domain and record payments against them.

## Authentication

All endpoints require a valid Sanctum Bearer token:
```
Authorization: Bearer {token}
```

## Authorization Rules

| Role | GET `/fines` | GET `/fines/{fine}` | GET `/me/fines` | POST `/fines/{fine}/payments` |
|---|---|---|---|---|
| `SUPER_ADMIN` | ✅ All fines | ✅ Any fine | ✅ | ✅ |
| `LIBRARY_STAFF` | ✅ All fines | ✅ Any fine | ✅ | ✅ |
| `MEMBER` | ❌ 403 | ✅ Own fines only | ✅ Own fines only | ❌ 403 |
| Guest | ❌ 401 | ❌ 401 | ❌ 401 | ❌ 401 |

> **Note:** Fine creation happens automatically via the Return domain (when an overdue book is returned). The API does **not** permit arbitrary creation or modification of fine amounts.

---

## Endpoints

### GET /api/fines
List all fines. Only accessible by `SUPER_ADMIN` and `LIBRARY_STAFF`.

**Query Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `search` | string | Searches loan number, member number, member name, book title, ISBN, barcode |
| `member_id` | integer | Filter by member |
| `loan_id` | integer | Filter by loan |
| `loan_item_id` | integer | Filter by specific loan item |
| `status` | string | `UNPAID`, `PARTIAL`, or `PAID` |
| `date_from` | date | Filter by `assessed_at` start date |
| `date_to` | date | Filter by `assessed_at` end date |
| `overdue_only` | boolean | If true, show only `UNPAID` and `PARTIAL` fines |
| `sort` | string | `assessed_at`, `amount`, `amount_paid`, `status`, `created_at` |
| `direction` | string | `asc` or `desc` (default: `desc`) |
| `per_page` | integer | Max 50, default 15 |

### GET /api/fines/{fine}
View a single fine with full details and payment history.
- Admin/Staff may view any fine.
- Member may only view their own fines (403 otherwise).

### GET /api/me/fines
Authenticated member's own fines. The member is always resolved from the authenticated user — the endpoint does not accept a `member_id` parameter. Returns `404` if the user has no member record.

**Supported Filters:** `status`, `date_from`, `date_to`, `sort`, `direction`, `per_page`.

### POST /api/fines/{fine}/payments
Record a payment against an existing fine. Only `SUPER_ADMIN` and `LIBRARY_STAFF`.

**Request Body:**
```json
{
  "amount": 1000,
  "paid_at": "2026-09-19T10:00:00+07:00",
  "payment_method": "CASH",
  "reference_number": "TRX-001",
  "notes": "Payment received at counter"
}
```

**Validation:**
- `amount`: Required, numeric, greater than 0. Cannot exceed outstanding balance.
- `paid_at`: Optional datetime. Defaults to server `now()` if omitted.
- `payment_method`: Required. One of `CASH`, `TRANSFER`, `OTHER`.
- `reference_number`: Optional, max 255 chars.
- `notes`: Optional, max 1000 chars.

**Security:** The following fields are **firmly ignored** even if provided: `status`, `amount_paid`, `outstanding_amount`.

---

## Fine Status Transitions

| Condition | Status |
|---|---|
| `amount_paid = 0` | `UNPAID` |
| `0 < amount_paid < amount` | `PARTIAL` |
| `amount_paid = amount` | `PAID` |

- `PAID` → Further payments rejected with `422`.
- Status transitions are server-controlled. Clients cannot force a status.

## Outstanding Balance

```
outstanding_amount = amount - amount_paid
```

The API always computes this server-side. It is exposed as `outstanding_amount` in the response.

## Error Responses

| Status | Scenario |
|---|---|
| `401 Unauthorized` | No or invalid token |
| `403 Forbidden` | Member trying to access all fines / pay / view another's fine |
| `404 Not Found` | Fine not found, or `/me/fines` with no member record |
| `422 Unprocessable Entity` | Validation error, overpayment, or fine already fully paid |
